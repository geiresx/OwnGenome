# Changelog

Each release's notes. From 1.0.0 on, a major or minor release has hand-written notes under `docs/releases/`, and the release workflow uses them as the release body. Older releases list their commits on GitHub.

## Unreleased

- The genome map shows where you are in the whole genome and lists what it draws. While a chromosome is open, a strip above the map draws every chromosome end to end, with the view as a brass brush and a tick for each finding on the map; a click on the strip opens a chromosome, and a drag brushes a new view or pans (on a phone the strip is a picture only). Under the map, an "In view" table lists every mark the map draws one by one in view: kind, what, where, size, who, copy and source, sorted by place with the findings first, a click on a header to sort by it. It shows 12 rows, then all of them (a scrolled list past 200 rows, at most 5,000), and a row flies the map to its feature. It follows the map once the map stops, announces only its count to a screen reader, and is folded on a phone; T folds and opens it. A closed result is never a row or a tick. One rule decides what the canvas, the strip and the table draw, and `og map build --predicate-table` writes the same rule's answers so a browser check holds the two to one set. A margin update no longer runs while the map is still moving: it waits for the view the map comes to rest on.

- The genome map on each person's page now zooms past the chromosome, to a region and down to a gene's exons. From the region level a genes lane draws every gene that fits, with the genes a finding names in bold; at the gene level each gene is a model with its strand and exon blocks, and a finding is a dashed tick with its change under it. A search box (`/`) finds a gene by name, a band, a finding on the map or a typed place; a click on a finding opens its card beside the map; a Nearest button flies to the closest finding when none is in view; Esc steps out one level at a time. Search, the card and Nearest offer only what the map draws, so a closed result is never suggested. The map's address keeps 3 decimals of Mb under 2 Mb and plain positions under 60 kb. A click on a finding on the map now opens its card instead of going straight to the finding's page; the card links there. `docs/genome-map.md` describes the map.

- Ordinary Russian, Ukrainian and Serbian text scans again. BMP regex case differences now refuse patterns that name a differing fold class under active case-insensitive flags. This includes negated classes and range interiors. Stable case-sensitive Cyrillic names work. The Unicode property guard and the astral casing guard still apply to text, filenames and exception rows. Indexed symlink target names receive the full filename guard before SKIP, including directory components. Both Unicode verifiers fail when an explicitly requested Python cannot run. CI requires Python 3.9, 3.12 and 3.15. A custom pattern refused by the case-difference rule now says so, with the file and line, and says what to change: turn the `i` flag off for that part and list the exact spellings.

- The scanner's Unicode checks install Python 3.9, 3.12 and 3.15 through pinned uv tooling, so the older oracle remains available on newer `ubuntu-latest` images.

- The personal-data scan refuses every astral cased character from UCD 13/15/16/17, including case-mapping targets. Text in Deseret, Osage, Old Hungarian, Warang Citi, Medefaidrin, Adlam and other astral cased scripts needs an ASCII SKIP glob. Uncased astral text still scans. Custom class ranges with a guarded interior return redacted exit 2. BMP verification now covers composite classes, ranges and alternatives on every available Python. Every working-copy symlink target gets the same redacted Unicode filename guard before following it.

- The personal-data guard now includes effective Python regex case relations, including Python 3.9 Cyrillic differences. Six stable older scalars pass again. Selected filenames get the same Unicode guard before exclusions, with a generic redacted error. Cached gitlinks and unreadable indexed objects fail with exit 2 unless skipped. Working-copy symlinks validate every hop, including directory components, with a 40-hop bound. The 248 newer stable scalars remain conservatively blocked.

- The personal-data scan fails closed with redacted exit 2 on Unicode-version-dependent text, patterns and ALLOW/SKIP entries. Its generated guard covers UCD 13/15/16/17 and unassigned scalars. Newer emoji and plain symbols still scan. Files with newer script letters need an ASCII SKIP glob. Invalid UTF-8 symlink targets now fail before exclusions in working-copy and index scans.

- The personal-data scan, the image scan and the version checks of CI now run in the Rust `og` binary: `og dev scan personal-data` (`scripts/ci/check-personal-data.sh`), `og dev scan images` and `og dev versions coupled` (`scripts/ci/check-images.sh`), `og dev versions check-run` (`scripts/ci/gen-containers-config.sh --check-versions`), `og dev versions expand` (`scripts/ci/check-links.sh`) and `og dev pgs` (`scripts/ci/check-pgs-labels.sh`). The scripts keep their options and lists; the Python inside them is gone. Fixes:
  - A personal-data scan that read no text file (every file skipped or binary) fails with `FAIL: no text file was scanned`. It printed `scanned 0 text files` and passed.
  - A personal-data scan whose root is reached through a symbolic link places each file under that root, so the lists of skipped files and documented examples still apply to it.
  - An image exemption in `check-images.sh` whose file no longer names that image fails with `FAIL: <file> no longer names <image>; drop its line from EXEMPT_PAIRS`. A stale exemption was never reported.
  - `check-links.sh` and `check-images.sh` read `versions.env` strictly: a line that is not a plain `NAME="value"` (with no `"`, `$` or backquote in the value), or a name set twice, fails the check and names the line. Before, such a line was skipped, so the URLs built from it went unchecked.
  - The PGS evaluation check never reads a JSON `true` as the number 1, so `"estimate": true` no longer matches an effect of `OR 1`.
  - Personal-data findings print only the kind, escaped filename and line number. Matched values and custom-pattern contents never appear in diagnostics. The Python scanner printed the detected line.
  - Built-in word boundaries and sample-label case folding follow Python, including combining marks, dotted and dotless I, long s and the Kelvin sign.
  - The staged scan uses NUL-delimited Git requests and responses, so a filename containing a newline cannot hide a finding.
  - Built-in and custom personal-data patterns share a Python-subset compiler and a backtracking matcher. Word boundaries stay inside the search, so a chip row ending in `A-` can backtrack to its shorter match. Unicode word, space and case rules also apply to custom patterns.
  - Empty custom matches keep Python's iteration order, including a nonempty alternative at the same position. Capture groups keep the full match when checking allowed examples.
  - Pattern files use universal newlines. ALLOW and SKIP rows use Python's line separators, so a CR or Unicode separator cannot extend an exemption into another file.
  - Custom patterns cannot quantify an operand that can match empty text. Such patterns stop with redacted exit 2 because their match spans can differ from Python and hide a finding under a partial exemption.
  - A filename with invalid UTF-8 stops the personal-data scan with redacted exit 2 in working-copy and index modes. It cannot be changed into another name or skipped.
  - Unsupported custom constructs or matcher resource limits stop the scan with a redacted error and exit 2. The supported subset is documented in `scripts/ci/check-personal-data.sh`.

- CI evidence rejects FASTA offset overflow and offsets outside the file before reading or publishing. Guard tests this in both debug and release builds. Every new dev verb fails on stdout or stderr write or flush errors. A truth VCF header after the first data record fails without replacing the destination.   - Step 07: a multi-base change of one length at an MT-RNR1 position was logged as "an insertion or deletion". It now reads "a multi-base change". Nothing else changes: no MT-RNR1 call is passed.
  - Step 07: `--min-depth 0` with a named MT-RNR1 position missing from the depth file crashed. That position now counts as depth 0.
  - Malformed input to any of the four (a record with too few columns, a `POS` that is not a whole number) now stops with exit 2 and a message that names the file and line, not a Python traceback.

- The CYP2D6 depth check and the RFC1 motif count, ported to the Rust `og` binary: `og pgx cyp2d6-bed`, `og pgx cyp2d6-measure` and `og pgx cyp2d6-check` (from `bin/cyp2d6_depth_check.py`) and `og str motif` (from `bin/rfc1_motif.py`) read BAMs with htslib, without pysam. Steps 21, 32 and 9b run them (see above); no option, output file or format changes.

- Genome map, first pieces, in the Rust `og` binary. `og map build` writes one person's map document: the chromosome bands, the runs of homozygosity, and every finding with a place on the genome (its own position, or its gene's span). A result the page keeps closed (a finding to act on, and APOE on every page) is tagged with its id on every row that could reveal it, so the page's own closed-result rule hides those rows too. `og map genes` builds the gene and exon files once per GENCODE release, offline. No pipeline output, option or page changes yet; the live page starts drawing the map in a later change. The format is in `rust/crates/og-map/README.md`.

- The run-log commands are now `og run state`, `og run eta`, `og run headroom` and `og run delta`, with the same options and the same output. The command lines of `bin/run_state.py`, `bin/run_eta.py`, `bin/run_headroom.py` and `bin/run_delta.py` are gone: run as commands they exit 1 and name the og command; the modules stay for the live site, its alerts, the database re-check and the summary, which import them. `scripts/generate-report.sh` writes the delta with `og run delta --newest-history <sample dir>`, so og picks the previous run by the one rule the summary uses too, and the report now needs og in `bin/.og/` (`scripts/setup.sh --og`), as steps 04, 05 and 07 do. On macOS, `bin/og` runs in a Linux container; docs/run-state.md says how to run the commands there.
  - `og run delta` copied every summary section once per section it compared and looked ClinVar hits up one by one. - Run logs in the Rust `og` binary. `og run state`, `og run eta`, `og run headroom` and `og run delta` read Nextflow traces, weblog messages, run-all.sh status and the per-box step history the way `bin/run_state.py`, `bin/run_eta.py`, `bin/run_headroom.py` and `bin/run_delta.py` do, and write the same files byte for byte; a parity test runs both on the same inputs. `og run tasks` gives the step of each trace row, and the Nextflow CI check of ClinVar reruns now reads the traces with it. Two fixes: a PRS percentile of 0 in the delta report now reads 0, not "none", in og and in `run_delta.py`; and `generate-report.sh` now compares a run with the newest `history/` folder that holds a summary.json, as the delta tool itself does: a newer folder without one, left by a copy that stopped half way, no longer stops the report with "the delta against the previous run was not written". og reads a trace memory cell such as "1.2.3 GB" as no value; the Python modules of the live alerts still stop on it.

- Rust building blocks for the ports that look things up by position. `og-io` reads the lines of a region from a bgzipped file through its `.tbi` or `.csi` index, as `tabix` prints them, reading only the blocks the index points at. `og-intervals` reads bases from an uncompressed FASTA through its `.fai`, as `samtools faidx` prints them, and refuses a compressed FASTA or a `.fai` that does not match the file. It also adds sorted interval sets (union, intersection, lookups by binary search, BED files such as the PAR regions) and reciprocal overlap. Nothing calls them yet, so no pipeline output, option or file changes.

- `og` runs natively on a Mac that hosts the live site, so the genome map works there too. `scripts/setup.sh --og` and each release now also make `og-darwin-arm64` and `og-darwin-x86_64`, and `bin/og` runs them on macOS. They are built without the new cargo feature `bam` (on by default, so the Linux builds are unchanged): the BAM tools say so and exit 2 there. `rust/og.sh check` refuses a stale macOS binary, and a release's `SHA256SUMS` lists all four.
